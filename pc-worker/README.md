# 好好唱资源 AI 整理器

让电脑替 NAS 生成人声分离伴奏。NAS 负责曲库与播放，整理器负责执行任务，网页显示当前模型、任务、CPU/内存/GPU 占用与日志。

## 启动

Windows 10/11 x64，解压后双击 `start.cmd`。首次安装会下载 Python、推理环境和模型，需要联网及数 GB 空间；下载失败可再次启动。后续复用已安装环境。

默认打开本机状态页，只监听 `127.0.0.1:8000`。关闭网页不会停止服务，关闭启动窗口会停止服务。

## 怎么连接

- **同一电脑上的 KTV 测试端**：PC 地址填 `http://127.0.0.1:8000`。
- **家中 NAS 调用**：停止助手，将 `worker.json` 的 `host` 改为 `0.0.0.0` 后重启；NAS 填能访问的 PC 地址。按自己的网络管理要求允许访问，此操作不是本机测试的必需步骤。
- 模型填 `htdemucs`，连接密钥在状态页复制。启用 NAS 后台的 AI 伴奏分离。

本项目不会自动修改网络或防火墙。公司网络建议保持默认回环模式。

## 显卡自动选择

| 检测结果 | 行为 |
| --- | --- |
| 支持的 NVIDIA 显卡、驱动和至少 4 GB 显存 | 选择相应 CUDA 运行库，启动时验证真实 GPU 运算 |
| RTX 50 / Blackwell | PyTorch 2.7.1 / CUDA 12.8，需兼容驱动 |
| 其他支持的 NVIDIA 显卡 | PyTorch 2.5.1 / CUDA 12.1 |
| 小显存 | 使用较短分段，减少推理显存需求 |
| AMD / Intel GPU、没有独显、驱动不兼容或 GPU 检查失败 | 明确显示 CPU 模式；当前未内置这些 GPU 的加速后端 |

默认模型 `htdemucs` 适用于上述设备；可在 NAS 手动比较耗时更长的 `htdemucs_ft`。设备选择解决兼容性，不保证每首歌曲的人声都能完美去除。CPU 模式通常更慢。

## 文件和问题

`worker.json` 保存端口、监听地址和连接密钥；`runtime` 保存环境；`data/models` 保存模型；`data/jobs` 保存任务、结果和日志。

界面显示“在线”只表示服务可连接。请用 NAS 实际准备一首普通 MV，确认任务完成并能切换伴奏。模型首次下载失败或任务失败时，可在 NAS 后台重试，详情看整理器任务日志。

完整流程见 [使用手册](https://github.com/xudong7587/haohaochang/blob/master/docs/USER-GUIDE.md)。
