# 好好唱后台：让收藏变成可唱的曲库

用户只需要找到喜欢的歌、收藏、开唱。后台负责保存可靠的来源、处理文件、建立播放版本；需要用户介入时，应说明哪一步出了问题以及下一步怎么做。

## 当前已实现

| 区域 | 当前能力 |
| --- | --- |
| 曲库 | 扫描本地媒体、NFO 歌名/歌手、同名海报、歌词、手动校正、标签筛选 |
| 整理 | 预览最近 500 首识别结果，逐首校正歌手/歌名/标签，批量保存和准备播放 |
| 下载接入 | 在线找歌下载；监听 `/download`，支持外部下载器的嵌套目录 |
| 自动入库 | 文件稳定约 60 秒后复制到 `/media/歌手/歌手 - 歌名.ext`，同名不同文件保留后缀，保留下载源文件 |
| 播放准备 | 串行转码，保存原唱；配置并启用兼容 AI 后自动分离伴奏；任务失败可重试 |
| 标签 | 男声、女声、组合、合唱；大陆、港台、欧美、日韩；语言和音乐风格标签 |
| TV | 娱乐首页、无人点歌时随机原唱播放、点歌优先、扫码和遥控器操作 |

原唱和伴奏的电视播放文件永久存于 `/data/cache`，正式曲库保留原始媒体、NFO 和可用海报/LRC。重复入库按下载源路径、大小、修改时间去重，尚不是音频指纹去重。下载源文件保留意味着会额外占用空间。

已有曲库的整理目前更改数据库中的显示信息，不重命名或移动现有媒体。新下载入库才创建规范目录和文件名。未识别歌手标记“待核对”；未分离资源显示“待分离”。没有配置 AI 时先准备原唱，配置后可批量准备伴奏。

## 内置收藏夹同步（默认方案）

后台填写收藏夹 ID 或带 fid 的链接，启用后自动检查、下载到 /download、识别信息、入库和分离。无需额外部署 bili-sync。首次同步包含已有收藏，每次最多读取 100 条，剩余分页在后续同步继续；默认每 10 分钟检查。受权限或风控限制时可填写自己的 B 站 Cookie，失败显示任务错误。

信息 AI 使用 OpenAI Responses API，可选 web_search 查证，模型和 API Key 在后台单独设置。低置信度或缺少必要信息进入“待核对”，补充后恢复流程。AI 模型并非事实数据库，仍需抽查；人工锁定信息不覆盖。

提供 GET /api/integrations/reviews 和 POST /api/integrations/reviews/:id 两个带独立凭证的接口，供企业微信/TG/webhook 适配器查询与回复。凭证只允许处理待核对信息，不能访问其他管理 API。当前未内置平台机器人，也不会自动给外部账号发送消息。

## 兼容已有 bili-sync（可选方案）

项目是 [amtoaer/bili-sync](https://github.com/amtoaer/bili-sync)，镜像名是 `amtoaer/bili-sync-rs`。它支持收藏夹自动同步、视频音频下载及 FFmpeg 合并，继续由它管理 B 站登录和收藏夹。

1. 建一个专门的「KTV」收藏夹，避免把教程、整场演唱会、非音乐视频混进自动流程。
2. 在 bili-sync 中把该收藏夹下载到独立 NAS 文件夹，例如 `/volume1/download/ktv`。
3. 好好唱 Compose 将同一文件夹映射为 `/download`。两个容器内的路径名称可以不同，左侧 NAS 实际路径必须对应同一目录。
4. 正式曲库映射到 `/media`，使用另外的目录，并允许写入。不要把下载目录和正式曲库嵌套在一起。
5. 后台开启自动整理，填好 AI 服务地址、模型和密钥，检测通过后启用。
6. 收藏视频后，由 bili-sync 下载，好好唱在文件稳定后自动复制整理、生成原唱并分离伴奏。失败记录留在“后台任务”，不会删除下载源文件。

当前采用文件夹衔接，不读取 bili-sync 数据库或 B 站 Cookie，也不需要额外 webhook。文件稳定只是下载完成的通用判断；最终还会用 FFprobe/FFmpeg 验证，失败显示任务错误。若下载器长时间暂停或 NFO 比视频晚到，需在完成后重试或再次预览整理。

核对过 bili-sync 的 [NFO 实现](https://github.com/amtoaer/bili-sync/blob/main/crates/bili_sync/src/utils/nfo.rs)：`actor` 是 UP 主，不能作为歌手；`genre` 可携带 B 站标签。当前只导入与内置标签精确匹配的值。没有可靠的歌手信息时，应由用户核对，不能把上传者直接当原唱歌手。

## 后续逐步补齐的后台能力（尚未实现）

### 下载接入与待整理

- 每个来源独立规则：收藏夹、UP 主、手工上传，设置默认语言、地区、用途和是否自动入库。
- 下载收件箱：显示原始标题、来源链接、完成状态、识别结果；不确定的歌曲先待审核（当前已有待核对入口，后续完善收件箱视图）。
- 过滤长视频、合集、无音轨资源；合集拆分成歌曲需要明确的分段依据。
- 支持下载完成通知，减少仅靠文件大小稳定判断的等待和误判。

### 歌曲和版本

- 区分“一首歌”和“一个视频版本”：官方 MV、现场、翻唱、不同清晰度归属同一首歌，选择默认版本。
- 文件哈希去重，再考虑音频指纹；提供对比和合并，不自动删除看似重复的表演。
- 试听原唱与伴奏，设置默认音轨、歌词偏移、音量；分离效果差时可保留旧版并重新生成。
- 同步展示缺海报、缺歌词、待补视频、待分离、分离失败、路径失效。

### 标签与歌手资料

- 声音/演唱形式、歌手地区、语言、年代、曲风分别管理。“欧美”是分类标签，不等于演唱语言。
- 建立歌手资料表，同一歌手的地区和演唱形式只需校正一次，后续歌曲继承。
- 保留标签来源与人工锁定；人工修正优先，不被下一次扫描覆盖。
- AI 可提供识别建议与置信度，但与人声分离使用不同能力和接口。不用人声分离模型判断歌手身份，不凭姓名或声音猜地区。

### 任务与维护

- 处理队列增加阶段进度、暂停、取消、定时和可配置资源上限，夜间预处理避免影响白天使用。
- 支持磁盘空间预警、保留策略、过期临时文件清理；删除前明确区分下载源、正式文件和可重建缓存。
- 数据备份与恢复、路径失效修复、数据库一致性检查、版本升级记录。
- 异地独立客厅、多用户权限和电视配对。当前仍是单客厅、单活跃播放器。

新增需求按“使用场景 → 自动流程 → 需要用户确认的例外 → 验收步骤”记录。优先把收藏到可唱这一条流程做稳定，再扩展来源和高级分类。

## 本地 PC 与 API 调度

Windows 支持包优先使用 NVIDIA GPU，默认 htdemucs，无需云端密钥。NAS 最多同时处理两个任务；PC 空闲优先 PC，忙时使用已配置的备用 API 并行处理另一首，PC 不可用或失败时自动尝试 API。备用接口需要兼容 ktv-separation-v1，商业平台各自协议仍需适配，不是任意 API Key 都可直接使用。
