## 已实现

曲库工作台分为待整理、半标准、标准三个分类。页面顶部可以解析 B 站或 YouTube MV 链接，查看识别结果并下载到待整理区。刷新曲库元数据会更新可靠匹配的歌名、歌手；不确定的结果留给人工核对。每首歌直接提供刷新歌名／歌手、解析／补充 MV、自动找歌词入口，展开后可修改资料、导入 LRC、保存与继续处理。

新播放资源按歌曲放在独立目录，包含一份画面、原唱音频、伴奏音频、歌词和资料 JSON。原唱／伴奏通过两路同步音频切换音量，画面不重新加载。缺视频但具备两份音频和歌词的歌曲归入半标准；缺少信息、歌词或任一音频的歌曲归入待整理。兼容旧播放资源，可手动提交迁移。

内置的是常见歌曲的起始目录，可按歌名、歌手和拼音检索，并支持导入更多目录。点选尚无本地资源的歌曲后，会尝试找音频、找同步歌词和调用分离服务。下载源不匹配、歌词缺失、PC 不在线等情况会留下待核对任务。

B 站链接保留分 P 页码，BV 文件名可以读取对应分 P 标题。收藏夹支持 bili-sync 常用凭证字段；普通链接下载也使用同一份 B 站 Cookie。ac_time_value 目前仅保存，没有实现自动刷新登录凭证。

字幕支持当前句着色、下一句预告、字体名称、字号、颜色与偏移。增强 LRC 使用逐字时间；普通 LRC 根据句时间渐进着色。纯音频使用浏览器实时频谱，不再为两种音频重复生成背景视频。

按用户要求，本地 9 条示例／测试歌曲（含《可爱女人》的两条记录）、队列与旧任务已清空；启动默认不再生成示例。原媒体移到项目 .tools 下的隔离目录，未永久删除。PC 与 API 连接配置保留。

## 本轮验证

- 23 项自动测试通过，包含真实 FFmpeg 处理、分离 API 协议往返、鉴权、队列、歌词匹配和目录识别。
- Edge 无头浏览器验证后台，无页面脚本错误。
- 独立测试歌房验证双音频播放、切换及暂停：切换不更换视频地址，播放时间前进，实测切换后音画偏差约 7 毫秒；不代表所有设备都能达到这一数值。
- 音频 Range 请求返回 206，手机 /control 页面返回 200，二维码接口正常返回。

## 仍需验证或补全

电视实际 WebView 的声音授权、同步效果和遥控器操作尚需实机验收。浏览器测试没有检验扬声器输出音质。重启前后的旧《可爱女人》迁移未完成最终验收，随后已按要求移出曲库。

目前没有完整的中文歌曲与歌词数据库，也没有已接入的 QQ／网易云／酷狗歌词适配器。已接入 [LRCLIB](https://github.com/tranxuanthang/lrclib)，会核对歌名、歌手与录音时长；网络与覆盖率会影响成功率。[LDDC](https://github.com/chenmozhijin/LDDC) 可作为后续中文逐字歌词适配的参考，目前可以手动导出 LRC 再导入。TuneScout-v2 仅作为产品流程参考，没有把它当作已经可用的歌曲下载 API。

新纯音频播放器已有实时频谱，图片轮播还没有迁移到新播放器。字体文件上传尚未实现，需在播放设备安装字体。旧重复歌曲尚无自动合并工具。新目录的资源健康检查、失败恢复与跨来源录音版本校验还需要完善；当前数据库分类不能代替定期文件校验。

外部平台下载到歌词再到 PC 分离的完整实网流程，尚未在本轮完成最终验收。配置真实聊天 API 后也需实测一次。遇到缺歌词或版本不符时保留待整理是预期行为，不能将此视为全自动成功。

## 后续自动化顺序

先把一首歌的获取流程做稳定：统一歌曲标识与录音版本，保存候选来源、时长和歌词依据；核对成功后下载原唱，分离伴奏并检查音频时长，三项齐全才进入半标准。视频候选需要核对剪辑版本和起始偏移，不能仅靠时长接近就认定同步。确认后再升级标准资源。

下一步接中文歌词来源适配器，补资源文件健康检查与幂等重试，再做重复歌曲合并、图片轮播、凭证自动刷新。最后完成电视、NAS 反代和手机的实机验证，再发布新版。运行过程应显示每一步耗时、失败原因和可重试入口，避免只显示“处理中”。

## 国内 API 选择

歌名、歌手和标签整理可以先试阿里云百炼千问，或 DeepSeek。后台选择 Chat Completions 协议与 JSON 输出，并填写服务商当前可用模型；这一接口不做人声分离。千问结构化输出能力见[官方说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)，DeepSeek JSON 模式见[官方说明](https://api-docs.deepseek.com/guides/json_mode/)。本项目完成协议支持，未用付费密钥验证具体模型。

没有 PC 时，可在 NAS CPU 或云服务器部署项目自带的 Demucs 分离服务，沿用 ktv-separation-v1 协议。NAS CPU 的速度取决于硬件和歌曲长度。若希望购买托管服务，可以评估[腾讯云数据万象人声分离](https://cloud.tencent.com/document/product/460/58433)：它通过 COS 存储与任务处理返回结果，需要新增腾讯云适配器，不能把腾讯云密钥直接粘贴进现有分离接口就使用。计费与音质应在购买前用自己的样曲验证。

## 接续优化 · 歌词、PC 启动与直接整理

PC 启动器将 venv 指向实际安装目录，修复桌面启动时的路径问题、错误日志占用与错误弹窗占用启动锁。已用健康检查和浏览器确认本机 CUDA 服务、PC 面板在线。进度页新增经过时间；模型日志存在百分比时显示模型进度。

待整理与半标准歌曲行提供直接整理按钮。已有歌曲的整理任务会检查资料、查找缺失歌词、准备音频并按配置调用分离；半标准会尝试找 MV。新视频链接通过替换操作或保存并继续整理生效，保持歌曲 ID。已可唱的双音频保留，只替换画面；待整理来源更新时清空旧歌词，重新匹配。新资源在独立目录完成后才切换当前指针，失败保留旧版本。新增真实 FFmpeg 替换回归测试，覆盖重复替换、音频保留和不匹配回滚。

R3 在新格式替换路径已修复；R2 增加同歌任务调度互斥和新编辑接口忙碌检查，但导入等其他交叉路径仍需完整覆盖。其余审查事项继续以任务表为准。歌词仍以 LRCLIB 候选和手动 LRC 为主，歌名／歌手／时长匹配不能保证录音或逐字节奏一致，尚无自动声音指纹或强制对齐服务。
