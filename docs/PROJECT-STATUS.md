## v0.3.13 连续播放与全屏遥控菜单

- 曲库新增跨所有分页的全选勾选，范围为当前分类及搜索结果；新增整个未隐藏曲库／所选歌曲的缺失歌词补充任务，保留已有歌词与音轨，播放队列内或整理中的歌曲跳过。后台持久任务支持失败原因与重试。147 项测试包含认证、全库范围、去重、修订冲突、查找失败、入队竞争与音轨字节保留；浏览器覆盖 45 首跨页全选、分批提交与全库入口。

- 根据用户实机反馈：TV 卡顿而平板 /play 流畅。确认 NAS 使用 Express sendFile 的 HTTP Range 文件直读，播放路由没有实时转码。原控制器每 100ms 检查音画差，超过 120ms 直接设置 currentTime；按用户要求删除整个周期校时定时器，开始／恢复、显式 seek、切换音轨与错误后备才做对齐。歌词只读取时钟。
- 歌词时钟移入独立 PlayerVisuals，避免约 30 次／秒更新整个 Player；显示层降到最多 20 次／秒，视频与音频原速解码。
- 全屏下键／确认键呼出菜单并聚焦暂停，方向键可移动到切歌和歌词按钮，首次唤醒及长按不触发操作。APK 保留在原沉浸式 WebView 内全屏，避免系统 custom video view 遮住网页控制层。
- 本地 147 项 Node 测试、生产构建与播放器浏览器回归通过。隔离测试覆盖无周期调度、视频人为慢速时没有自动 seek、错误后备时钟、V2 文件 HTTP 206，以及全屏下键／确认唤醒、暂停／继续、歌词调整和切歌。真实双音频、接管、自动播放拦截、歌词与旧资源回归通过；雷鸟 TV 实际流畅度未在本机验收，生产 NAS 未改动。

## v0.3.6 B站登录、真实高清与分轨整理

2026-09-10，以 main `1590caf` 为基线。发布状态以 [v0.3.6 Release](https://github.com/xudong7587/haohaochang/releases/tag/v0.3.6) 和 Actions 为准。

- 已复现 480p 根因：用户 NAS 已保存完整 bili-sync 字段，但 B站 nav 返回未登录；旧 yt-dlp 选择器允许低清回退，下载后没有分辨率下限校验。不是未填写独立 Cookie，也不是采用了 TuneScout。
- 在线找歌与在线资源设置增加扫码登录和状态检测，管理员完成登录后 NAS 保存共享 Cookie；普通点歌端可查看是否登录并进入管理端扫码。扫码域名兼容 B站当前 `account.bilibili.com`。凭证不返回客户端，失效时明确提示。

- 画面交 PC 单独裁剪，独立音频按同一时间区间裁剪后送分离；正式资源保留分辨率。相同音频重复导入可提升画面质量而不重新分离。资源信息记录来源和实际高度，曲库显示画面高度。

## v0.3.5 后台负载、高清与电视操作

- 诊断文件导出时 3 项运行、155 项排队，运行阶段为 NAS 画面／音轨准备，PC 为 CUDA 三路。原所有 API 共用每 IP 每分钟 120 次，后台与媒体请求可阻塞控制和心跳。现分别限制认证、读取、媒体、播放控制、心跳和写入；429 提供 Retry-After，未取消写入保护。
- 后台任务阶段使用独立 tasks 通知，曲库和任务通知各自每 2 秒最多一条，播放状态即时发送。设置定时刷新只读取管理状态，PC 短时读取失败保留上次进度；NAS FFmpeg 解码／编码最多两线程、滤镜单线程并尽可能降低进程优先级。画面、原唱、伴奏转换与校验分别显示 FFmpeg 实际百分比，进度不写持久化设置。
- B站预览新增最高可用及当前账号可用分辨率选项，显示浏览器实际预览与下载可用高度；同分辨率优先高码率。预览为兼容性保留 AVC，下载可选更高清的其他编码，切换清晰度保留位置和裁剪标记。下载任务和缓存区分清晰度，新选择的缓存还区分 Cookie，旧在途任务兼容原缓存。下载选择失败不默默变成纯音频。
- NAS 与新版 PC 画面转换保留源分辨率，不再固定降至 1920 宽。大会员权限需要把会员账号最新 Cookie 保存到 NAS 的在线资源设置；网页登录不会同步凭证，实际档位取决于片源和账号。已有低清资源不会自动重下载，需要重新选择高清来源。
- 歌词提供提前／延后各 0.5、3、10 秒按钮，累计范围仍为 ±30 秒，可复位。遥控左右键仅在演唱画面获得焦点时微调；导航按钮上的方向键正常移动焦点。演唱画面确认键或明确的全屏按钮可全屏，原生 API 不可用时铺满当前 WebView，返回键退出；全屏时焦点限制在播放器内。APK 加强初始与退出全屏时的焦点恢复。
- 本地 97 项 Node 测试、17 项 Python 测试与前端构建通过；浏览器覆盖方向键进入右侧功能、按钮全屏、返回、WebView 后备全屏、六个歌词步进、清晰度切换与裁剪标记。真实 NAS/TV 遥控器、大会员账号下载和家庭网络长时间满载播放尚需升级后实机验收，不将模拟平台或浏览器结果当作实机通过。

需要同时升级 NAS、PC 整理器和 TV APK；保留现有配置、数据和媒体目录。

## v0.3.4 资源空间与处理速度

- 用户实机 RTX 4070 SUPER、GPU 加速、htdemucs。诊断日志中最近三首 PC 分离分别为 8、10、10 秒且没有重叠；NAS 任务在资源准备阶段停留数分钟。抽查来源为 3840×2160 AV1；此前在 NAS 转码、复制版本并重复解码校验。
- 未改变的画面／音轨使用硬链接共享磁盘数据，不支持时回退复制；编码仍写新文件后原子替换，不覆盖旧版本。导入后的原始视频不再复制到仅更新资料的版本。编码输出完成一次完整解码后缓存校验证据，后续依照大小、修改时间和路径复用；改动或损坏仍触发验证。
- NAS 启动后及每 15 分钟安排回收。当前资源可用、没有播放／在途任务引用、超过 10 分钟宽限期的已知旧版本和孤立暂存可回收；来源引用、未知文件、链接目录和当前版本保留。旧格式生成的受管缓存视频在新格式可用后也会回收。可用于升级前积累的版本，诊断导出包含最近清理记录。
- 标准曲库恢复“整理已有标准曲库”，每批 20 首逐项提交；旧格式迁移到独立画面、原唱与伴奏，已合格 v2 不重新去人声、不新增无用版本。保留已有资料、歌词和音轨，跳过播放中／有任务的歌曲。
- PC 增加 `video-prepare-v1` 能力，通过原有上传、幂等和任务结果协议返回无声 H.264。优先 NVIDIA 解码、CUDA 缩放、NVENC 编码；失败时 PC CPU 后备。旧 PC 未声明此能力时继续 NAS 旧流程。新流程覆盖准备、补画面和画面修复；NAS 校验后发布，失败保留此前资源。
- 本地真实 CUDA 对照使用 RTX 5080 Laptop、htdemucs、7 秒分段、三份各 180 秒的合成音频。单路依次完成三份为 26.80 秒，三路全部完成为 17.25 秒；任务阶段采样平均 GPU 占用分别 34.8% 和 56.3%。该结果仅适用于本地合成输入，不能代表家庭 PC 歌曲表现。
- 本地用用户来源的 20 秒 4K AV1 片段验证，硬件路径约 5.70 秒，输出 1920×1080 H.264、20.02 秒、无音轨，完整解码通过；不包含网络与 NAS 入库耗时。家庭 PC 的完整吞吐仍需升级后验收。
- Windows 状态读取与原子替换竞争可使后台任务抛出 PermissionError 并停在 queued；协议查询和 PC 面板现共用 JobStore 读写锁。
- 本地 92 项 Node 测试、15 项 Python 协议／并发测试、生产构建、曲库／PC／设置浏览器验证通过，真实三路 CUDA 与硬件画面转换通过。生产 Z 盘仅做只读调查，未直接删除文件或改写 NAS 数据库。
