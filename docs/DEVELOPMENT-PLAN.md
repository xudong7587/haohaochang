# 模块边界与本轮开发顺序

目标：第一次点歌可以逐步准备，后续点歌直接读取正式曲库。NAS 是资料和任务的唯一管理端，播放端与 PC 执行端不各自维护另一份曲库。

## 模块职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 曲库 `library` | 歌手/歌名、NFO/海报、导入与人工修订 | 外站搜索、模型推理 |
| 正式资源 `assets` | 原文件、原唱、伴奏、可视化视频、版本记录与迁移 | 队列、页面 |
| 在线源 `sources` | 各平台搜索/下载、链接校验与来源记录 | 判定一首歌已可唱 |
| 资源获取 `acquisition` | 缺歌任务、候选匹配、先音频后 MTV、待人工处理 | 直接操控播放器 |
| 信息识别 `enrichment` | 结构化歌名、歌手、标签与证据 | 音源分离、凭空编造歌词 |
| 音频画面 `visualization` | 频谱与图片循环，生成一次永久保存 | AI 语义识别 |
| 分离 `separation` | PC 优先、API 后备、上传/取回伴奏 | 管理下载收藏夹 |
| 任务 `jobs` | 持久化状态、阶段、重试、并发与通知 | 混入所有业务步骤 |
| 播放 `playback` | 队列、单播放器、原唱/伴奏、QR 与互动 | 下载、AI 计算 |
| PC 整理器 | 设备探测、模型运行、任务与资源状态页 | 拥有 NAS 曲库的主记录 |

`app.js` 只逐步保留组合、认证和路由；已有实现按经过测试的模块边界迁出，不做一次性无验证的大搬家。模块通过歌曲 ID、任务 ID、资源路径和结构化结果协作。

## 固定规则

- 原始资源与成功处理结果都属于正式曲库，没有自动过期策略。
- 旧 `/data/cache` 是历史位置：迁移验证成功后再使用新路径，不能直接删除旧数据。
- 生成文件必须先写临时文件、完成校验后发布；失败不替换已可唱版本。
- 音频快唱与后台 MTV 补齐是两项任务。后台补齐不得打断当前歌曲。
- 信息或版本不确定时进入待处理，保留来源、候选及失败原因。
- PC 本机默认只监听回环地址；公司网络测试不探测、不修改局域网或防火墙。
- 已完成的状态须有文件与测试证据，UI 不显示伪造进度。

## 本轮执行顺序

1. **PC 可用性**：自动检测 GPU/CPU、兼容环境、真实分离回传；资源 AI 整理器图标和状态页。
2. **正式曲库**：独立资源模块、保留原文件和双版本、兼容旧数据；确认重扫不会重复入库生成文件。
3. **纯音频播放**：NAS 生成频谱与背景循环；底部同步歌词；人工补 MTV 后切换主视频并保留旧版本。
4. **缺歌获取**：独立在线源和获取流程；自动音频候选匹配、准备、后台找 MTV；找不到进入待处理。
5. **交付**：简明 README、独立使用手册、最新 Release、本机预览与 PC 状态页同步。

以上是验收顺序，不表示尚未实现的条目已经可用。逐项结果记录在 `VALIDATION.md`。

## 参考项目的使用范围

- [TuneScout-v2](https://github.com/yuwancumian2009/TuneScout-v2) 的公开仓库目前展示 README、截图与更新记录；可参考多源匹配、整理与缺失资料修复的产品流程，不能据此声称已经取得其完整实现源码。
- [bili-sync](https://github.com/amtoaer/bili-sync) 用于参考收藏夹分页、增量同步与文件元数据。它是收藏内容同步工具，不能替代歌名语义匹配与 KTV 版本判断。

音频画面由 NAS FFmpeg 完成；PC 集中做人声分离；AI API 用于信息识别，兼容的分离 API 用于 PC 不可用时后备。所有成功结果保存后复用。
