# 好好唱使用手册

本地本轮新增功能见 [开发状态](PROJECT-STATUS.md)，尚未发布到 Release。正式安装先装 NAS，再连接播放设备和手机，最后启用自动下载与 PC 算力。[所有安装文件在 Latest Release](https://github.com/xudong7587/haohaochang/releases/tag/latest)。

## 1. 安装 NAS

导入 `docker-compose.yaml`，只修改密码、端口和三个目录。

| 配置 | 说明 |
| --- | --- |
| `ADMIN_PASSWORD` | 至少 12 位管理密码 |
| `43210:3210` | 左侧是自己的 NAS 端口，右侧固定 3210 |
| NAS 设置目录 → `/data` | 设置、数据库、任务记录；必须持久化 |
| NAS 曲库目录 → `/media` | 正式媒体库，需要读写权限 |
| NAS 下载目录 → `/download` | 下载入口，与正式曲库分开 |

镜像 `ghcr.io/xudong7587/haohaochang:latest` 公开拉取。无需登录、无需 `.env`，也无需自己创建设置文件。

启动后打开 `http://NAS-IP:端口/admin`。用管理密码登录，其余设置保存在后台。普通部署只用主 Compose；`docker-compose.ai.yaml` 是可选 NAS CPU 分离容器，使用 PC 或 API 时不用装。

旧部署增加 `/download`，移除曲库映射末尾的 `:ro`，保留旧密码、端口和数据目录。更新时在 UGOS 重新拉取并重建，或运行：

```sh
docker compose pull
docker compose up -d
```

## 2. 整理已有歌曲

1. 曲库工作台顶部粘贴链接，点击“解析 MV 链接”，核对结果后下载；已有文件可通过设置页扫描曲库。
2. 使用“刷新曲库元数据”批量更新可靠匹配的歌名、歌手，或点击歌曲行的“刷新歌名 / 歌手”查看单首结果。
3. 点击“自动找歌词”或导入 LRC，使用“解析 / 补充 MV”填写视频链接。
4. 保存并继续整理，后台任务显示处理结果。音轨序号、左右声道等设置在“音轨高级设置”。

待整理区接收缺资料、歌词或双音频的歌曲；半标准区包含原唱、伴奏和歌词；标准区还须有视频。空曲库不会自动生成示例歌曲。

| 原文件 | 设置与结果 |
| --- | --- |
| 普通 MV / 普通音频 | 原始音频；分离后才能提供伴奏 |
| 纯伴奏 | 不做分离，没有原唱版本 |
| KTV 双音轨 | 指定伴奏和原唱的音轨序号，从 0 开始 |
| KTV 左右声道 | 指定 0 左 / 1 右，先试听确认 |

普通立体声不等于原唱、伴奏各占一个声道。已有文件的“整理”修改资料，不自动重命名或移动原文件。

系统读取同名 NFO、`musicvideo.nfo`、`movie.nfo`；歌手来自明确的 artist 字段，不把 UP 主当歌手。封面可用同名 JPG/PNG、同名 `-poster.jpg`、目录 `cover.jpg` 等。

标签可手动选男声、女声、组合、大陆、港台、欧美、语言、曲风等；AI 可辅助填写，但需要核对不确定信息。

## 3. TV 和网页歌房

电视安装 `haohaochang-tv-0.1.0-debug.apk`，填写 NAS 根地址并登录。遥控器菜单键修改地址，方向键选择，确定键操作，返回键关闭弹层或返回点歌页。

没有电视时，在管理后台点击“打开网页歌房”，独立打开 `/play`。同一浏览器可以复用登录后的客厅凭证；新设备由主人首次登录一次。浏览器首次可能需要点击“开始播放”以允许声音。

无人点歌时随机播放原唱；点歌准备好后接管播放，队列结束后恢复随机播放。默认使用已有伴奏，普通 MV 未分离时只能播放原唱。

全屏二维码固定在右上角。已点列表每 30 秒出现约 6 秒，显示当前与接下来 3 首，空队列不显示。

所有终端共用一个歌房，只允许一台活跃播放器。切换电视/网页播放时，关闭原播放页，另一台会自动重连。

## 4. 手机扫码点歌与互动

扫描播放画面中的二维码即可加入，无需安装 APK，也不用输入网址和密码。手机需能访问二维码指向的 NAS 地址。

手机可按歌名、歌手和标签找歌，调整待唱队列，暂停、切歌、切换原唱/伴奏，并发送掌声、礼花、爱心和星星。置顶不会打断当前歌曲。

二维码包含客厅凭证，只分享给一起唱歌的人。手机不负责录音或麦克风返听；麦克风连接实际音响/混音设备。

## 5. 好好唱资源 AI 整理器（PC）

下载 `haohaochang-resource-ai.zip`，在 Windows 10/11 x64 解压并运行 `start.cmd`。第一次需要下载 Python、PyTorch 和模型；网络失败可重新启动。以后复用环境。

程序先检测显卡和驱动，选择运行环境。兼容 NVIDIA GPU 使用 CUDA，小显存使用短分段；没有支持的显卡、驱动不兼容或实际 CUDA 检查失败时回退 CPU。目前不包含 AMD/Intel GPU 加速后端。

默认模型为 `htdemucs`；高级用户可在 NAS 比较耗时更长的 `htdemucs_ft`。状态页显示实际任务阶段、日志，以及整机 CPU、内存和 GPU 占用。

默认只监听 `127.0.0.1:8000`，不改局域网或防火墙。在同一电脑的 KTV 后台填写：

| PC 设置 | 值 |
| --- | --- |
| PC 地址 | `http://127.0.0.1:8000` |
| 模型 | `htdemucs` |
| 密钥 | 从整理器状态页复制 |

若由家中另一台 NAS 调用：停止程序，在 `worker.json` 将 `host` 改为 `0.0.0.0` 后重启，NAS 填可达的 PC 地址；网络权限按自己的环境设置。公司网络测试保持回环模式。仅有 NAS 的公网反代，不能让 NAS 自动连回异地 PC。

PC 空闲时优先使用；忙碌或离线时可由配置的兼容 API 后备，最多并行两项任务。备用服务须支持 `ktv-separation-v1`，不能直接填普通聊天 API。没有后备且 PC 不可用时，任务保留错误，恢复后重试。

配置在 `worker.json`，环境在 `runtime`，模型和任务在 `data`。重复打开快捷方式会进入已有服务；关闭网页不停止服务，关闭启动进程才停止。桌面程序的详细说明见 [PC 说明](../pc-worker/README.md)。

## 6. 下载、找歌与信息 AI

在后台启用在线资源。在“在线找歌”填写歌名和歌手，选择“自动找歌并点唱”：

**搜索匹配 → 提取音频 → 正式入库 → 准备画面与可用伴奏 → 加入点歌队列 → 后台寻找 MTV。**

Bilibili/YouTube 搜索依赖 NAS 出网和平台可用性。匹配不可靠或处理失败时进入后台“待核对”，可补信息或资源链接。此流程不保证所有歌曲都能找到，也不绕过平台登录、付费或访问限制。

后台找到 MTV 会保存候选路径并通知管理员。请试听确认版本、长度与节奏后，在歌曲编辑页关联视频；候选不会直接覆盖正在使用的版本。找不到 MTV 时，音频版仍可唱。

B 站收藏夹可以在后台直接监控：填收藏夹链接或 `fid`，不是用户 UID。首次同步包含已有收藏，每轮最多 100 项并继续分页。按需填写自己的 Cookie。也可以让现有 bili-sync 下载到相同 `/download`，同一收藏夹建议只用一个下载入口。

下载目录中的文件稳定约 60 秒后自动整理到“歌手 / 歌手 - 歌名”。源文件保留，信息不确定的先待核对。

“AI 歌曲信息识别与刮削”单独填写支持 Responses 或 Chat Completions JSON 输出的地址、模型和密钥，可选联网查证。它识别歌手、歌名和标签，不做人声分离，也不能凭空保证准确歌词。测试按钮会调用一次真实 API。

## 7. 只有音频时怎么唱

新播放格式使用浏览器实时频谱，不额外生成整首背景视频。图片轮播尚待迁移到新播放器，旧格式已有的背景视频仍可兼容播放。

同名封面用于背景；还可在音频旁建立“文件名.images”目录放 JPG/PNG，最多使用 5 张，约每 12 秒循环切换。没有图片时使用默认背景。此视频不等于真正 MTV，后台仍标记“待补视频”。

歌词放在同名 UTF-8 `.lrc`，或在编辑页粘贴。带时间戳时显示底部当前句/下一句，并按句时间渐进填色；增强 LRC 使用逐字时间，普通 LRC 的着色按句时间估算。没有时间轴则显示普通文本，不伪造同步。

补充 MTV：先放进正式曲库，再在歌曲编辑页关联容器内路径并重新准备。已有源文件和历史播放版本保留。

## 8. 正式文件、备份和维护

`/media` 保存曲库原文件；`/media/好好唱播放资源/歌曲` 按歌手、歌名和 ID 保存新资源，每首有 `画面.mp4`（有视频时）、`原唱.m4a`、`伴奏.m4a`、`歌词.lrc`、`歌曲信息.json`；处理记录与旧资源保留。生成目录不会被扫描为重复歌曲，没有自动过期删除策略。

旧 `/data/cache` 文件在歌曲使用/准备时复制到正式目录，旧文件不自动删除。迁移完成前请一并保留。此目录是历史兼容位置，新产物不再以临时缓存对待。

备份 `/data`、正式曲库及需要保留的 `/download`。停服后备份数据库最简单。原文件、双版本和历史文件都会占空间，当前没有自动容量清理；管理员需关注剩余空间。

## 9. Lucky 反代和常见问题

外部 `https://域名:端口` → Lucky → `http://NAS-IP:宿主机端口`。容器后端使用 HTTP。出现 TLS handshake 错误时，检查后端是否误填 HTTPS。

在 NAS 后台保存完整外部根地址，不附加 `/admin` 或 `/tv`，TV 填相同地址。重新打开播放页后，二维码会使用反代地址。代理应保留认证/Range 请求并允许 `/api/events` 持续输出，证书需被电视信任。

| 问题 | 先检查 |
| --- | --- |
| 扫码打不开 | 手机能否访问 NAS；二维码地址是否更新 |
| 播放失败 | 歌曲是否准备好；当前是否有另一台播放器 |
| 入库失败 | 曲库挂载是否可写；文件是否仍在下载 |
| 分离失败 | PC/API 连通性和整理器任务日志 |
| 下载失败 | NAS 出网、平台限制、Cookie |
| Docker 子网重叠 | Compose 指定子网是否与已有网络冲突 |

日志命令：`docker compose logs --tail=100 ktv`。

企业微信/TG 目前没有内置机器人。后台提供独立凭证和 `GET /api/integrations/reviews`、`POST /api/integrations/reviews/:id`，供自己的集成读取、处理待核对任务。

## 10. 建议验收顺序

本地歌曲播放 → 手机点歌/掌声 → PC 分离一首并切换伴奏 → 纯音频频谱/歌词 → 收藏夹或自动找歌 → 外网播放。

本机 RTX 5080 已跑通真实分离和 NAS 回传；真实歌曲音质、4070 Super、电视硬件和平台下载仍需分别验收。[详细验证记录](VALIDATION.md)。


## v0.2.0 曲库整理变化

编辑期间若另一窗口或后台更新歌曲，页面会保留草稿并提示冲突；比较后选择采用最新资料，或明确保留草稿再保存。批量刷新会逐首显示结果。移出曲库的歌曲可以在“已隐藏”页恢复。

补 MV 前需要试听确认同一录音版本并填写画面偏移，已有原唱、伴奏和歌词会保留。画面候选可以确认、拒绝或重新搜索。歌词支持手动 LRC 和可配置的本地中文索引，配置见 [开发说明](DEVELOPMENT.md)。

设置页可配置纯音频播放时的背景图片轮播。若设备阻止自动出声，点击播放器的重试／开启声音入口；音频不可用时会显示具体错误。
