# 好好唱 · 四端使用说明

适用于 0.1.0 家庭测试版及本轮自动曲库更新。先安装 NAS，再连接电视和手机，最后启用 PC 分离及收藏夹自动化。

## 四个终端各管什么

| 终端 | 安装方式 | 用途 |
| --- | --- | --- |
| NAS 管理端 | Docker Compose | 保存曲库、下载、整理资料、调度人声分离、转码和输出视频流 |
| TV 端 | Android APK | 随机原唱开场、遥控器点歌、播放和接收互动 |
| 网页歌房 | 浏览器打开 `/play` | 没有电视时，在电脑等设备播放，与 TV 使用相同客厅 |
| 手机端 | 扫码打开网页 | 搜索点歌、调整队列、控制播放和发送表情，无需 APK |
| PC 分离端 | Windows 支持包 | 使用 CPU/GPU 生成伴奏，结果交回 NAS 保存 |

NAS 是必需的；PC 可以随时关闭。已有播放缓存的歌曲无需再次分离。当前所有终端共享一个客厅，只允许一台活跃电视播放器，不支持家里和外地各唱各的。

## 1. Docker / NAS 管理端

### 下载与部署

在 [测试版下载页](https://github.com/xudong7587/haohaochang/releases/tag/test-0.1.0) 下载 `docker-compose.yaml`，或下载包含 APK 和说明的 `haohaochang-0.1.0-nas-test.zip`。镜像公开，无需登录 GHCR。

在 UGOS Docker 中新建项目，修改以下项目后启动：

| 配置 | 填写方法 |
| --- | --- |
| 镜像 | `ghcr.io/xudong7587/haohaochang:latest` |
| 管理密码 | 修改 `ADMIN_PASSWORD`，至少 12 位 |
| 端口 | 例如 `43210:3210`，只改左侧 |
| 持久化目录 | NAS 实际目录映射到 `/data` |
| 正式曲库 | NAS 实际曲库映射到 `/media`，需要写入权限 |
| 下载目录 | 独立目录映射到 `/download`，不要和正式曲库相互嵌套 |

不要创建 `.env`。其余设置在网页保存，系统自动生成 `/data/settings.json`。普通部署只用主 Compose；`docker-compose.ai.yaml` 是可选的 NAS CPU 分离服务，使用 PC 时不必安装；`docker-compose.build.yaml` 和 GitHub workflow 文件供开发使用。

打开 `http://NAS-IP:43210/admin`，输入管理密码。根地址也会进入管理页。映射左侧目录必须是 NAS 上真实存在、容器有权限访问的路径。

### 首次整理已有曲库

1. 点击“扫描曲库”，读取 `/media` 内的媒体、NFO、海报和歌词。
2. 打开“整理曲库”，预览歌手、歌名和标签，修改不准确的信息后保存。对已有文件，此操作更新曲库记录，不批量移动或重命名原文件。
3. 编辑歌曲，先“检测媒体音轨”，再按文件实际情况选择普通 MV、纯伴奏、双音轨或左右声道。
4. 点击“保存并准备播放”，或者在整理页批量准备。任务结果在“设置与任务”查看，失败可重试。

同名 `.nfo`、`musicvideo.nfo`、`movie.nfo` 可提供资料；明确的 artist 字段用于歌手，不把 B 站 UP 主或 NFO actor 自动当成歌手。海报支持同名图片、同名 `-poster`/`-thumb` 图片和目录中的 `poster.jpg`、`folder.jpg`、`cover.jpg` 等。歌词使用 UTF-8 同名 `.lrc`，也可以在歌曲编辑窗口补充。

普通 MV 的左右声道通常都有音乐和人声，不要当成 KTV 双声道。双音轨序号从 0 开始，需要试听确认。纯伴奏文件没有原唱版本；未分离的普通 MV 也不会自动变成无声伴奏。

### 下载到正式曲库的流程

在“设置与任务”开启下载目录自动整理。文件写入稳定后，系统执行：

下载到 `/download` → 读取文件名/NFO → 可选 AI 信息识别 → 信息不确定则待核对 → 复制到 `/media/歌手/歌手 - 歌名.ext` → 准备原唱 → 启用分离时生成伴奏 → 可点播。

下载目录每 30 秒检查，文件需连续两次稳定且最后修改超过 60 秒，所以刚复制进去不会立即入库。下载源保留；不是自动剪切。相同源文件会去重导入，但目前不是按音频指纹识别不同来源的同一首歌。

只有音频也能入库，以封面/背景加歌词播放，并标记“待补视频”。时间同步需要带时间戳的 LRC；系统不会凭空生成准确歌词或原版 MV。以后在编辑窗口填写容器内视频路径进行补充。

### 收藏夹监控、信息 AI 与标签

在“B 站收藏夹自动下载”填写收藏夹 ID 或带 `fid` 的链接；这里不是用户 UID。保存后可立即同步，也可启用定时检查。首次同步包括已有收藏，每轮最多读取 100 项，后续继续分页。需要账号访问时可填写 Cookie，实际下载仍取决于平台限制和 NAS 网络。

已有 bili-sync 用户也可以共用下载文件夹，让它下载、好好唱负责整理；同一收藏夹建议只选一个下载入口，避免两边重复下载。

“AI 歌曲信息识别与刮削”是独立设置，可填写支持 Responses 和结构化输出的 API 地址、模型、密钥；联网查证还需要服务支持 `web_search`。信息不足会进入“待核对”，补歌手和歌名后继续入库。已有歌曲可选中后触发 AI 刮削，手工确认的信息优先。

当前标签包括男声、女声、组合、合唱、大陆、港台、欧美及语言、曲风、现场、MV、伴奏等。它们是可编辑的歌曲标签，并非已经建立完整歌手资料库。AI 根据可用资料识别，不能保证每首都正确；当前不会自动从网上下载歌手写真或补齐所有海报。

企业微信、Telegram、webhook 已预留独立管理接口，可读取待核对项目并提交歌手、歌名；专用机器人和主动推送尚未内置。接口说明见本页末尾。

## 2. TV APK

下载并安装 `haohaochang-tv-0.1.0-debug.apk`。首次打开填写 NAS 根地址，例如 `http://NAS-IP:43210`，不要添加 `/admin`；连接后输入管理密码。APK 自动进入电视页面，菜单键可重新设置服务器。

| 操作 | 方式 |
| --- | --- |
| 移动焦点 / 选择 | 遥控器方向键 / 确定键 |
| 返回 | 关闭二维码、退出歌手筛选或回到歌名点歌 |
| 修改 NAS 地址 | 遥控器菜单键 |
| 搜索歌曲 | 歌名、歌手、拼音或首字母；也可在手机输入 |
| 播放控制 | 页面上的暂停、继续、切歌、原唱/伴奏和全屏按钮 |

默认进入“音乐现场”。无人点歌时随机播放曲库中可用的原唱，已准备好的点歌会接管播放；队列唱完后回到随机原唱。空曲库或未准备完成时需要先入库、等待处理。点歌默认使用可用伴奏，纯伴奏不能切出原唱。

点播未准备的歌曲会在 NAS 建立任务，准备好后加入队列，不保证点击就立刻播放。电视只接收播放流，本身不执行下载、转码和分离。

本轮网页功能由 NAS 更新提供，已有 APK 无需重装。当前 APK 为测试签名，最低 Android 6，要求较新的系统 WebView；具体雷鸟遥控器键值和解码能力仍需实机确认。模拟器无法代替硬件验收。

## 网页歌房：没有电视也能唱

NAS 后台右上角点击“打开网页歌房”，会在独立标签页打开 `/play`。同一浏览器已有客厅凭证时直接进入；新设备首次由主人登录一次。页面与 TV 一样随机播放原唱、接收点歌、切换伴奏和显示互动，可点击全屏。部分浏览器首次需点击“开始播放”以允许声音。

在网页歌房显示二维码，让来宾扫码即可点歌，不需要告诉他们网址或管理密码。二维码指向 NAS 的 `/mobile` 页面并携带客厅凭证，不连接播放电脑；配置外部访问地址后会使用反代地址。来宾仍需具备访问该地址的网络条件。网页歌房和 TV 共用播放器名额，切换设备时先关闭原播放页。

## 3. 手机扫码点歌与互动

1. 在电视打开“扫码点歌”，手机扫描二维码，用浏览器打开。
2. 二维码含当前客厅凭证，正常扫码不必再次输入管理密码。手机需能访问二维码中的 NAS 地址。
3. 按歌名、歌手或标签找歌，点选后加入共享队列；也可以先填自己的称呼。
4. 在“已点歌曲”查看队列，置顶或移除待唱歌曲；当前歌曲不会被置顶操作打断。
5. 使用播放控制切歌、暂停、切换原唱/伴奏；点击掌声、礼花、爱心或星星，电视会显示对应表情。

手机是点歌和控制端，不承担唱歌录音或麦克风返听。麦克风与音乐应接到实际音响/混音设备。

如果扫码提示登录，重新打开电视二维码再扫一次。若一直“连接中”，先用手机浏览器确认服务器地址可访问。后台改访问地址后，重新打开电视页面以生成新二维码。本地预览只监听电脑回环地址，预览二维码不能给其他手机使用。

## 4. PC 人声分离助手

下载 `haohaochang-pc-worker.zip`，解压到固定目录，双击 `start.cmd`。支持 Windows 10/11 x64，无需手动装 Python 或 Docker。首次会下载 Python、CUDA 版 PyTorch 及依赖，需要联网和数 GB 空间；首次分离还会下载模型。

保持窗口打开，在 NAS“AI 伴奏分离”中启用功能，并填写：

| 设置 | 值 |
| --- | --- |
| PC 地址 | 助手窗口显示、NAS 可达的 `http://PC-IP:8000` |
| PC 模型 | 先用 `htdemucs` |
| PC 连接密钥 | 助手窗口显示的密钥 |

如电脑有多个网卡，选择与 NAS 互通的地址。Windows 防火墙提示时允许专用网络。窗口应显示 NVIDIA 显卡名称；如果显示 CPU，检查驱动和环境。点击 NAS 的“检测服务”，保存后选一首普通 MV 准备播放，观察 PC 日志和 NAS 任务。

助手一次执行一个推理任务。NAS 最多并行处理两项任务，规则如下：

| 情况 | 行为 |
| --- | --- |
| PC 在线且空闲 | 优先 PC |
| PC 忙且配置备用 API | 另一首可交给 API，并行处理 |
| PC 离线或请求失败 | 尝试备用 API |
| PC 忙但无备用 API | 在 PC 排队 |
| PC 不可用且无备用 API | 保留失败任务，恢复后可在后台重试 |
| 已有原唱/伴奏缓存 | 直接复用 NAS 文件 |

备用 API 需兼容 `ktv-separation-v1`。不能直接填写普通聊天 API 或任意分离网站的网址；服务商协议不同需要适配器。信息识别的 API 密钥与音频分离是两套独立配置。

关闭助手窗口即停止服务，无需为已缓存歌曲一直开电脑。处理途中掉线会等待请求失败后回退，并不是立即无缝切换；远端已开始的任务也不保证被取消。

助手的端口、密钥和设备选项保存在 `worker.json`，模型和任务在 `data`，错误日志在 `data/jobs/任务ID/worker.log`。本地推理不上传云端；启用 NAS 备用 API 后，走备用服务的音频会发送到该服务。

4070 Super 的实际推理速度和音质尚待你的设备验收。先用 `htdemucs` 完成一首，试听人声残留和乐器损失，再考虑比较耗时更长的 `htdemucs_ft`。

## 外网与 Lucky 反代

外部 HTTPS 地址 → Lucky → `http://NAS-IP:43210`。后端使用 HTTP，不能因为外部是 HTTPS 就把后端也填成 HTTPS。日志出现 `tls: first record does not look like a TLS handshake` 时先检查这一点。

在 NAS 后台“NAS 访问地址”保存完整外部根地址（含非标准端口），TV APK 填相同地址；重新打开电视页面，手机二维码随之更新。使用独立域名根路径，保留认证头和 Range 请求，允许 `/api/events` 的 SSE 长连接，避免实时接口被缓冲。证书需要被电视信任。

外网视频仍由 NAS 提供，上行带宽影响流畅度。PC 可以留在 NAS 的局域网内，不需要为了外地电视单独暴露 PC 服务。外网与内网仍共享同一个客厅。

## 更新、备份与排错

UGOS 中重新拉取 `latest` 并重建容器，保留原密码、端口和三个目录映射；旧部署增加 `/download`，去掉 `/media` 映射末尾的 `:ro`。命令行等价操作为：

```sh
docker compose pull
docker compose up -d
docker compose logs --tail=100 ktv
```

备份 `/data` 和正式曲库；下载源需要保留时一并备份 `/download`。`/data/settings.json` 保存设置和密钥，`/data/ktv.sqlite` 保存记录，`/data/cache` 保存播放版本。旧版 `/data/downloads` 继续兼容，新下载使用 `/download`。停服后备份数据库最简单，更新前不要清空持久化目录。

原文件、正式曲库副本、双版本缓存都会占空间，目前没有自动容量回收或硬件转码。任务失败先看后台错误，再看 Docker/PC 日志；下载失败检查出网和平台限制，入库失败检查目录写权限，伴奏失败检查 PC/API，播放失败先确认歌曲已准备。

Compose 已显式指定 Docker 子网。如提示 `Pool overlaps`，换一个与现有网络不重叠的私有子网，不需要删除其他项目的网络。

## 管理交互接口

后台“待核对”下展开“企业微信 / Telegram / webhook 管理接口”，查看独立集成凭证。机器人适配程序使用 `Authorization: Bearer <凭证>` 调用：

- `GET /api/integrations/reviews`：读取待核对项目。
- `POST /api/integrations/reviews/:id`：提交 JSON，例如 `{"artist":"歌手名","title":"歌名"}`，确认后继续处理。

此凭证只能处理待核对资料，不是完整管理员权限。目前由接入程序主动读取接口，没有内置平台消息推送。

## 建议的首次实机验收

按顺序检查：一首本地歌曲播放 → 手机扫码点第二首和送掌声 → 普通 MV 经 PC 分离并切换原唱 → PC 关闭后用已配置的兼容 API 处理另一首 → 收藏夹下载一项并核对入库 → 外网 TV 连接。

本轮自动化已覆盖媒体处理、PC/API 调度、曲库整理与页面联动；真实 GPU 推理、收费 API、收藏夹下载成功率及电视硬件仍需实机确认。详细记录见 [验证记录](VALIDATION.md)。
