# 好好唱使用手册 · v0.3.13

按第一次安装、准备歌曲、开唱和日常维护的顺序使用本手册。[最新安装包](https://github.com/xudong7587/haohaochang/releases/latest)中包含 NAS 部署文件、TV 应用和 Windows 资源整理器。

## 1. 安装 NAS

NAS 保存歌曲与歌房状态。只需运行一份主服务，电视、手机和 PC 都连接它。不要让两个容器同时使用同一个数据库目录。

### 选择部署方式

| 情况 | 配置文件 | 默认访问地址 |
| --- | --- | --- |
| Linux NAS，使用电视与 PC 自动发现 | `docker-compose.lan.yaml` | `http://NAS-IP:43210/admin` |
| 普通 Docker 桥接，手动连接 PC | `docker-compose.yaml` | `http://NAS-IP:3210/admin` |
| 额外在 NAS 上运行 CPU 分离容器 | `docker-compose.ai.yaml` | 可选，使用 PC 时通常不需要 |

LAN 与普通配置二选一。LAN 使用 host 网络，通过 `PORT` 修改端口，不填写 `ports`；普通配置修改 `端口:3210` 左边的数字。桥接配置的容器子网不是 NAS 家庭 IP；若与现有容器、LAN 或 VPN 冲突，需要换成空闲子网。

### 修改配置并启动

从 `haohaochang-nas.zip` 解压配置，在 NAS Docker 管理器创建 Compose 项目，检查：

| 配置 | 怎么填写 |
| --- | --- |
| `ADMIN_PASSWORD` | 自己设置至少 12 位管理密码，替换示例值 |
| `/data` 的左侧目录 | 保存数据库、设置、队列和任务；升级不要更换或删除 |
| `/media` 的左侧目录 | 正式曲库，需要读写权限，不加 `:ro` |
| `/download` 的左侧目录 | 下载暂存，与正式曲库分开 |
| 访问端口 | 选择 NAS 上空闲的端口 |

例如 `/volume1/music/ktv:/media` 表示 NAS 的 `/volume1/music/ktv` 在容器中叫 `/media`。使用自己的真实目录，不要原样复制他人的 `/volume3/...` 路径。无需额外创建 `.env` 或手动编辑数据库。

启动公开镜像 `ghcr.io/xudong7587/haohaochang:latest`，打开对应的 `/admin` 页面，用管理密码登录。其余设置从页面保存。

从桥接迁移到 LAN 时，先停止旧容器，再用原来的三个目录和密码启动新配置。

## 2. 连接播放设备与手机

### Android 电视

安装 `haohaochang-tv.apk`，首次启动约用 8 秒寻找同一局域网中的歌房。找到一个直接连接，多个则让你选择；没有找到可手动输入 NAS 根地址，例如 `http://192.168.1.20:43210` 或 `https://ktv.example.com`。粘贴带 `/admin`、`/tv` 的地址也会自动去掉页面路径。

自动发现使用 UDP 43212，NAS 的 LAN 配置已启用；已有 LAN 部署的 `KTV_DISCOVERY_ENABLED=1` 也会启用电视发现。普通 Docker 桥接、访客 Wi-Fi 或跨网段可能收不到广播，此时手动输入地址。只升级 APK 无法给旧 NAS 增加发现服务，需要同时升级 NAS。

电视首次显示登录二维码，用手机扫描并确认。手机若未登录，需要主人先登录再确认电视。电视会保存 NAS 地址与歌房登录状态。

方向键移动焦点，确定键操作；返回键先关闭弹窗、退出全屏或返回上一级，在根页面连续两次返回退出。菜单键打开连接设置和应用更新。最低 Android 6，网页已增加旧 WebView 的兼容脚本和启动失败重试界面；老设备仍建议更新 WebView，播放取决于系统解码能力。

### 网页歌房

后台点击“打开网页歌房”，或访问 `/play`。同一浏览器可以复用登录后的歌房凭证，新设备先登录或扫码。浏览器若拦截自动出声，点击“开始播放”或播放按钮。

### 手机

扫描歌房二维码进入 `/mobile`，不用安装应用。手机必须能访问二维码中的 NAS 地址；在后台保存正确的对外访问地址，二维码才会指向可用地址。

手机可点歌、调整已点列表、暂停、切歌、切换原唱／伴奏，以及发送掌声、礼花、爱心和星星。置顶下一首不会打断正在播放的歌。手机不负责录音或返听，麦克风连接音响或混音设备。

二维码带有歌房访问凭据，请分享给一起唱歌的人。

### Android 手机直接播放

同一个 APK 可以安装在 Android 手机上，自动进入本机播放器 `/play`，支持横竖屏切换。也可直接用手机浏览器打开 `/play`。登录后在这台手机出声，可切换原唱／伴奏、显示歌词和全屏播放；需要连接 NAS，共用歌房曲库和队列。扫码进入 `/mobile` 则继续只做遥控点歌。

### 哪台设备出声？

所有终端共用一个歌房。TV 优先于网页歌房，新开的同类播放器可以接管旧播放器；被接管的页面停止发声，不能继续切走当前歌曲。TV 离线后，网页歌房会在租约过期后恢复接管。`/mobile` 仅控制歌房；手机 APK 与 `/play` 按网页播放器参与播放接管，TV 仍优先。

## 3. 安装 Windows 资源整理器

整理器让 PC 执行裁剪、视频兼容转换和音频分离。完成的资源由 NAS 收回并保存，PC 不是曲库主机。

1. 在 Windows 10／11 x64 下载 `haohaochang-resource-ai.zip`，解压到固定位置。
2. 双击 `start.cmd`。首次下载 Python、PyTorch 等环境，可能占用数 GB 并耗时较长；后续复用环境和模型。
3. 启动成功后出现整理器窗口和右下角托盘图标。重复启动会复用已有服务。
4. 在 NAS 后台启用 PC 整理与伴奏分离。使用 LAN 部署时保持自动发现开启，等待 NAS 连接。

首次安装未完成时，NAS 显示未连接。可查看 `runtime/launcher.log`；下载中断后再次双击启动即可重试。程序不会自动修改防火墙。

### 自动连接与手动连接

自动发现要求 NAS 和 PC 位于可互通的家庭局域网。Linux NAS 使用 LAN Compose；访客 Wi-Fi、不同 VLAN 或 Docker 桥接可能挡住广播。

无法自动发现时，在 NAS 的 PC 连接设置中填写 PC 的局域网地址和端口，默认工作端口为 8000。连接密钥可在整理器“查看详细任务 → 高级：手动连接”复制。不要用 `127.0.0.1` 连接另一台电脑。

通过 NAS 的 `/pc` 页面可查看 PC 状态，使用 NAS 反代域名也一样；浏览器不用直接访问 PC 工作端口。

### 查看状态、隐藏和退出

窗口显示 GPU 名称与占用、显存、CPU、内存和当前任务。数值代表整台电脑；编码／解码和计算可能由不同引擎完成，不能只凭计算占用判断是否用了显卡。详细任务页还有阶段、日志、分组和分页。

点击右上角关闭或“隐藏窗口”后继续后台处理。双击托盘图标或再次运行 `start.cmd` 重新打开。使用“退出整理器”停止服务；有任务或更新时会提示先完成或取消，避免中断工作。

支持的 NVIDIA 显卡会选择兼容 CUDA 环境并验证真实 GPU 运算；不兼容时回退 CPU。当前没有内置 AMD／Intel GPU 加速后端。GPU 默认最多并行 3 首，CPU 默认 1 首；可在 `worker.json` 将 `concurrency` 改为 1～3，重启生效。显存紧张时先降低并发。

## 4. 整理已有文件

把媒体放入映射的曲库目录，在后台设置页扫描。空曲库不会自动插入示例歌曲。

| 分类 | 代表什么 | 接下来做什么 |
| --- | --- | --- |
| 待整理 | 原始文件、资料待核对，或缺少双音轨 | 确认歌名与演唱者，点击开始整理 |
| 半标准 | 原唱和伴奏可用，画面待补 | 已经可以点歌，以后再补 MV |
| 标准 | 原唱、伴奏和画面均已准备 | 直接点唱 |
| 已隐藏 | 从点歌曲库移出，媒体仍保留 | 需要时恢复 |

歌词缺失不阻止普通整理，也不改变以上分类。“可补充：同步歌词”不表示歌曲不能播放。

曲库默认展开歌曲，工具栏可筛选、排序，切换“行列表／海报墙”。需要分组时再勾选“按歌手分组”。每页 20 首，选择可以跨页保留；批量工具明确显示作用于已选歌曲还是当前筛选结果。

勾选“全选（所有分页）”会选中当前分类和搜索结果的全部歌曲，“本页”只选择当前页。切换分类或搜索条件会清空选择。

顶部“补充全部缺失歌词”可一键为整个未隐藏曲库查找歌词；也可勾选歌曲后使用“补充所选缺失歌词”。任务在 NAS 后台执行，关闭页面不影响处理。已有歌词（包括手写文本）保留，播放队列内或整理中的歌曲会跳过，结束后可再次点击。无匹配或来源连接失败会在“整理任务”显示原因，可重试或手动导入 LRC。自动查找匹配歌名和实际演唱者，保存来源；节奏仍可在播放时微调。

### 编辑歌曲

每首歌只有一个“编辑歌曲”入口，窗口内分为：

- **歌曲资料**：歌名、演唱者、标签和音轨设置。识别结果先进入草稿，确认后保存。
- **视频画面**：解析链接、预览候选、关联或替换画面、填写视频偏移。
- **同步歌词**：自动查找、导入 LRC 或手动编辑，试听后保存。
- **维护操作**：高清升级、兼容转换、隐藏与删除等。封面预览与替换在“歌曲资料”页。

处理中、成功和错误反馈会在编辑器内显示。后台刷新不会直接抹掉未保存的草稿；其他任务已修改资料时，先比较冲突内容再保存。

### 原唱和伴奏怎么设置？

| 原始文件 | 处理方式 |
| --- | --- |
| 普通 MV／普通音乐 | 保留原始音频，用 PC 或分离 API 生成伴奏 |
| KTV 双音轨 | 试听后指定原唱与伴奏音轨，序号从 0 开始 |
| 左右声道分别放原唱／伴奏 | 左声道 0、右声道 1，先试听确认 |
| 只有伴奏 | 保留伴奏，还需要原唱才能形成双版本 |

普通立体声不等于原唱、伴奏各占一个声道，不要仅因为有两个声道就这样设置。

扫描会读取同名 NFO、`musicvideo.nfo`、`movie.nfo`；实际演唱者来自明确的 artist 信息，不直接把上传者当歌手。资料可以手动修正。

## 5. 在线找歌与手机临时点歌

### 手机找一首曲库没有的歌

1. 本地搜索无结果时点“去在线找歌”，或直接打开“在线找歌”。
2. 填歌名和实际演唱者，搜索 B 站视频。
3. 打开候选试听。长合集可以标记开头和结束；不标记则用全部视频。
4. 点击“整理并点歌”。NAS 下载，PC 按需裁剪和分离，准备好后自动加入已点列表。
5. 手机“找歌进度”显示等待、处理或需要管理员核对的任务。

没有合适视频时，点“先找音频 + 歌词”。先尝试 B 站，再尝试后备来源，按歌名与演唱者匹配音频、查找 LRC、生成伴奏；音频可用后开唱，画面后续再补。音频可能是 M4A 等格式，不要求原站提供 MP3。

手机选择的视频下载或处理失败时会改走音频方案。PC 离线则等待连接，不重复派发。歌词或录音版本不能可靠确认时，会留下核对提示，不保证每首歌都能立即找到。

手机任务在等待队列中优先于管理页面的找歌，后续入库等步骤保留优先级。已经开始的任务继续完成，不为插队强行中断。后台已排队的同一请求会复用并提高优先级。

### 管理端导入

管理端也支持 B 站搜索、预览和裁剪。“加入曲库”只整理入库，不自动插入家庭已点队列。曲库顶部“添加链接”可以直接解析资源，核对歌名和演唱者后下载。

清晰度取决于账号权限和平台资源。会员高清需要在 NAS 保存对应账号的有效 B 站登录信息，单独在浏览器登录不会同步。不要把 Cookie 或登录二维码放进公开日志、Git 或截图。

收藏夹导入与定时下载在“设置与任务”的在线资源配置。遇到风控、失效链接或未开放资源，先看任务错误，再检查账号与原链接。

## 6. 歌词、字幕与时间微调

### 自动查找为什么找不到？

自动整理优先查本地索引，再依次查 QQ 音乐、网易云音乐和 LRCLIB。需要同歌名、同演唱者和带时间戳的 LRC；自动匹配允许已知时长相差最多两分钟，缺少时长不直接拒绝。兼容 Live／现场版等常见后缀、标点差异与合唱者顺序，不会把另一位演唱者直接当成同一版本。

编辑器支持 QQ 音乐、网易云音乐和 LRCLIB；自动选择时优先本地索引，再依次尝试 QQ、网易云与 LRCLIB，也可用“歌词来源”单独指定。无需提供音乐平台账号；可获取范围仍由平台决定，来源无法连接时可切换。

手动查找展示歌词的歌手、版本、专辑和时长，点击“预览歌词”核对，再用“使用这份歌词”载入草稿。多份结果、不同演唱者或不同版本不会直接覆盖当前草稿。时长差过大、同名不同歌手会明确提醒，尤其要防止同名的另一首歌。最后点击保存才替换歌曲歌词；自动整理仍要求歌名、演唱者和时长符合规则。

候选不代表节奏已正确，试听后再保存。不合适时导入自己的 `.lrc`，或编辑文本框。支持逐句时间戳、增强逐字 LRC 和毫秒 offset，不会把纯文本凭空变成准确的同步歌词。

### MV 已有字幕

在 `/play` 或 TV 点“隐藏歌词”，同时关闭**系统叠加的滚动歌词、倒数和歌词时间微调控件**。视频自身字幕保留。“显示歌词”恢复；浏览器／TV 保存这个选择。

同一浏览器中的网页歌房和 TV 网页同步偏好，另一台设备有自己的设置。已经烧录进视频的字幕无法通过这个开关移除。

### 歌词太早或太晚

显示歌词时，用歌词提前／延后按钮微调，或在演唱画面按左右方向键。调整只影响当前演唱显示，不改视频文件或歌词来源，可以一键重置。

开发用只读预览端口允许查找和查看 LRC 草稿，但不保存到 NAS。保存、整理、下载和资源修改需要正式管理端；这是预览保护，与匹配条件无关。

## 7. 封面、画面与存储

整理后自动补封面，已有缺封面歌曲也会后台分批补充。优先本地封面、视频封面或匹配的歌曲／专辑图片，没有时尝试歌手照片，再用同歌手专辑图片后备。失败保留原来可用的图，不反复高频请求。

更换封面：打开“编辑歌曲 → 歌曲资料”，当前封面会显示在左侧。点击“去 B站搜索封面”，可修改关键词、翻页并选择多个搜索结果中的一张；这里只读取视频封面，不下载或关联视频。也可点“上传封面”，选择不超过 8 MB 的 JPG、PNG 或 WebP。透明图片保存为白底 JPEG，画面保持比例。

选中后先显示新封面预览，点击“保存封面”立即生效；已有封面可以反复替换。取消选择、文件无效或下载失败会保留此前图片，不修改音轨、歌词或视频。本地 NAS 只读预览支持搜索和图片预览，保存需到正式 NAS。

补 MV 或升级画面不会默默替换已有原唱和伴奏。不同录音版本可能对不齐，需要试听并填写视频偏移。默认保留原编码、分辨率与帧率；电视不支持时再选择“转换兼容画面”。

标准资源是一份画面加独立原唱、伴奏和歌词。旧格式可在“标准曲库 → 曲库维护 → 老版本多视频合一”整理。清理保护播放中、排队或处理中的歌曲；失败输入和仍被引用的资源保留。受管目录中不再需要的重复视频，以及成功导入的下载输入，会按规则回收。

“移出曲库”只隐藏，可恢复。“删除”先列出将永久删除的文件或歌曲目录，再确认执行。整首歌曲目录里的其他文件也可能被删除，操作前看清预览。播放、排队或处理中的歌曲需先结束相关任务。

## 8. 更新 NAS、TV 与 PC

### 第一次升级到带更新器的版本

从 v0.3.9 或更早版本升级，TV 和 PC 先手动安装当前最新版一次；无需先安装中间版本。

- **TV**：从 v0.3.10 起使用固定发布签名。旧 debug 包若提示签名不一致，卸载后再安装，并重新填 NAS 地址、扫码登录。卸载不会保留旧登录。
- **PC**：等任务完成并退出旧整理器；旧版没有退出入口时，确认空闲后关闭旧服务进程。把新版文件覆盖到原目录，保留 `worker.json`、`runtime`、`.venv`、`data`，再运行 `start.cmd`。不要把整个旧目录删掉。

### 后续 TV 更新

遥控器菜单键 → “检查应用更新” → 查看新版 → “下载更新”。应用读取 GitHub 最新正式 Release，校验文件与签名，再打开 Android 系统安装器。

Android 8 以上可能要求允许好好唱安装应用。按提示打开系统设置，允许后返回继续，由系统确认。同签名覆盖保留 NAS 地址与登录。厂商限制安装器或无法访问 GitHub 时，仍可手动下载 APK。

### 后续 PC 更新

在窗口、托盘、详细页面或 NAS `/pc` 点“检查更新”，发现新版后点“安装新版”。

流程为下载校验 → 暂停接收新任务 → 等当前任务完成 → 备份程序 → 替换 → 重启并检查服务。下载和等待阶段可取消；安装与重启阶段等待完成。NAS 可能短暂显示未连接。

配置、模型、环境、任务数据与日志保留。替换失败或新版启动检查失败会恢复旧程序，备份和安装日志在 `data/updates`。这不代替整机备份；断电或磁盘损坏后应检查日志与备份，必要时手动恢复。

### NAS 手动更新

在 Docker 管理器拉新镜像、重建容器，保留密码、端口和目录映射。命令行方式：

```sh
# 普通部署
docker compose pull
docker compose up -d

# LAN 部署
docker compose -f docker-compose.lan.yaml pull
docker compose -f docker-compose.lan.yaml up -d
```

TV 网页界面随 NAS 更新；APK 更新改变原生外壳；PC 更新改变本机程序。Release 会说明需要更新的部分。

## 9. 外网与反代

先确认家庭内网能登录、点歌和播放，再把 HTTPS 反代指向 NAS 主服务。在后台保存真实对外根地址，重新显示二维码。

反代需支持持续事件连接、媒体 Range 请求和较长处理等待，避免代理缓冲导致状态不刷新。TV 必须信任域名证书，不依赖跳过证书错误。

PC 工作端口无需暴露到互联网。用 NAS `/pc` 看状态，NAS 在家庭网络内连接 PC。手机扫内网 IP 后换到蜂窝网络通常无法继续访问，需要使用已配置的对外地址。

## 10. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 后台打不开 | 容器是否运行、端口是否对应当前配置、NAS 地址是否正确 |
| 扫码后连不上 | 手机能否访问二维码地址；后台对外地址是否正确 |
| PC 未连接 | 首次环境是否装好、服务是否启动、自动发现或手动地址是否正确 |
| PC 使用 CPU | 查看设备信息、NVIDIA 驱动与显存；不支持的 GPU 会回退 |
| 显存不足／分离失败 | 降低并发，关闭占显存的程序，在 NAS 任务详情重试 |
| 下载失败 | 检查链接、B 站账号权限和平台状态；手机可先找音频 |
| 歌词找不到 | 区分来源连接失败和无匹配；确认演唱者，手动查找或导入 LRC |
| MV 有两套字幕 | 隐藏系统歌词；视频字幕不受影响 |
| 电视黑屏或卡顿 | 先验证网页播放；检查编码支持，必要时转换兼容画面 |
| 另一端没声音 | 查看谁持有播放权；TV 优先，旧播放器被接管会静音 |
| 关 PC 窗口后仍在工作 | 这是隐藏到托盘；用“退出整理器”停止空闲服务 |
| 更新检查失败 | 设备需访问 GitHub；保留当前版本，稍后重试或手动安装 |
| 更新后仍是旧版 | 确认旧服务已退出、启动目录正确，查看更新日志 |

NAS `/pc` 可导出诊断日志，包含任务阶段与有限日志片段。发送前仍需检查自己的内容；原始配置里的密码、Cookie 与 PC 密钥不要公开。

更多依据见[验证记录](VALIDATION.md)和[开发说明](DEVELOPMENT.md)。真实电视、家庭网络与歌曲仍需实机验收，自动化通过不等于每台设备都已验证。

## 11. 歌星资料与演唱界面

后台“歌星管理”点击歌手进入详情，顶部为歌手照片和介绍，下方以瀑布流展示歌曲。点击歌曲封面打开完整编辑器，点击“试听”预览原唱。点击“编辑歌星资料”可获取歌手照片、搜索 B站图片、上传照片、填写或查找介绍，预览核对后分别保存。后台会尝试补齐缺失照片；没有可靠结果时可手动设置，已有照片和手写介绍会保留。

自动图片来自匹配的 Apple Music 歌手页面，缺图时可能使用同歌手专辑图；短介绍只采用 Wikidata 中单一、同名演唱者条目并保留来源。找不到可靠资料不会编写生平。照片与介绍保存在 NAS 的 `/data` 中，独立于歌曲音视频。

网页歌房和 TV 的“歌星点歌”展示相同资料与深色歌曲墙，点击歌曲加入队列。歌词控制栏在 TV 舞台或全屏正在播放时闲置 4 秒隐藏；任意按键、触摸或移动鼠标显示。全屏下按下键或确认键打开底部控制菜单并聚焦暂停／继续；方向键选择后确认，可切歌、切换原唱／伴奏、调整歌词或退出全屏。第一次唤醒与长按唤醒不会误暂停或退出全屏。暂停、播放被拦截或错误时不会隐藏。

歌曲封面由 NAS 自动居中裁成方形、限制尺寸并铺白底，B站选图和上传均不需要 PC 整理器。v0.3.12 修复了旧 FFmpeg 处理透明封面可能失败的问题；失败仍保留旧封面与音轨。

## 12. 连续播放与电视卡顿

NAS 通过 HTTP Range 提供画面、原唱、伴奏文件地址，由电视或浏览器解码，不在播放时实时转码。v0.3.13 取消播放中的周期音画校时：开始后连续播放，允许小幅时间差。开始／恢复播放、主动拖动进度、切换音轨和错误后备才会对齐；歌词只读取音频时间，不会改动视频进度。

本次修复主要由 NAS 网页更新提供，v0.3.12 APK 也能使用。全屏菜单与画面保留在 APK 同一个 WebView。平板播放流畅时，仍需在电视上确认具体视频的解码与家庭网络表现；不要因这一差异重新分离已经可用的歌曲。
