# 好好唱 0.1.0 实机测试

镜像和 APK 已公开下载，无需 GitHub 账号，也不用配置 .env。

完整操作请阅读本包的“四端使用说明.md”，或仓库中的 [四端使用说明](https://github.com/xudong7587/haohaochang/blob/master/docs/USER-GUIDE.md)。

1. 在 UGOS Docker 中创建项目，粘贴本包中的 docker-compose.yaml。
2. 修改 ADMIN_PASSWORD 管理密码（至少 12 位）、左侧宿主机端口、/data 左侧持久化路径、/media 左侧实际曲库路径、/download 左侧下载目录。曲库需要可写，下载目录不要与曲库嵌套。不要修改容器内 /data、/media、/download 和右侧 3210。
3. 拉取并启动。后台打开 http://NAS-IP:你设置的端口/admin。
4. 输入管理密码。其余设置全部在后台完成，系统自动写入持久化目录中的 settings.json，无需手工新建文件。
5. 电视安装 haohaochang-tv-0.1.0-debug.apk，填写同一个 NAS 地址并登录。菜单键可重新设置地址。手机扫描电视二维码即可点歌。

若旧版部署提示 `all predefined address pools have been fully subnetted`，将本包新版 Compose 中的 `networks` 段加入原项目后重新部署，保留原有密码、端口和目录。新版显式使用容器子网 `10.253.231.0/24`；若提示 `Pool overlaps` 或与局域网/VPN 重叠，需换成未占用的私有子网。电视仍填写 NAS 地址，无需修改 NAS 网络或删除其他容器网络。

先用本地视频测试伴奏、原唱切换和手机点歌；双音轨须根据实际文件配置。再测试纯音频 + LRC、在线搜索及 AI。APK 是家庭测试签名版，电视需具备现代 WebView。

可选本地 AI 服务使用单独的 docker-compose.ai.yaml，与主文件合并启动：

```sh
docker compose -f docker-compose.yaml -f docker-compose.ai.yaml up -d
```

然后在后台填写 AI 服务地址 http://separator:8000、模型 htdemucs，API Key 留空。首次模型下载和 CPU 推理需要等待。第三方 AI 用户只需在后台填写兼容服务的信息，无需启动此容器。

更新主服务：

```sh
docker compose pull
docker compose up -d
```

故障日志：

```sh
docker compose logs --tail=100 ktv
```

主镜像：ghcr.io/xudong7587/haohaochang:latest
可选 AI 镜像：ghcr.io/xudong7587/haohaochang-separator:latest
源码：https://github.com/xudong7587/haohaochang

镜像为 linux/amd64；数据目录保存 settings.json、SQLite 曲库、下载资源及转码缓存。请保持该目录持久化，更新镜像无需重新配置。

## TV 连接与 Lucky HTTPS 反代

NAS 根地址默认跳转管理页 /admin，电视点歌页为 /tv。TV APK 首次启动填写服务器根地址，之后按遥控器菜单键修改；连接后输入 Compose 中的管理密码。

Lucky 的外部入口可以使用 https://ktv.example.com:666，后端目标必须填写 http://NAS-IP:宿主机端口。例如端口映射 43210:3210 时，后端端口填 43210。容器自身不提供 HTTPS；如果日志出现 tls: first record does not look like a TLS handshake，请检查后端是否误填为 https。

通过内网进入后台“设置与任务”，把“NAS 访问地址”保存为完整外部地址（包括 HTTPS 和非标准端口，不附加 /admin、/tv）。TV APK 填写相同外部地址，手机二维码也会使用该地址。留空时二维码跟随当前页面地址。

反代应覆盖整个独立域名根路径，保留 Host（包括端口）、Authorization 和 Range 请求头，并允许 /api/events 持续输出 SSE；不要缓冲实时事件或缓存带凭证的接口与媒体。证书需被电视系统信任。API 通过管理密码或客厅凭证验证身份，不限制请求 Origin，避免反代改写地址后误拒绝登录。Nginx 类代理可参考 [官方代理文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html) 的 proxy_buffering 和 proxy_read_timeout 设置。

外网开唱仍由 NAS 准备媒体，电视接收视频流；流畅度取决于家庭上行和电视网络。同一个后端目前只有一个共享客厅队列、一个活跃播放器，家里和外地不能同时独立开唱。

本次更新：新增 /download 映射；/media 必须可写（移除 :ro）。将 bili-sync 的 KTV 收藏夹下载目录映射到 /download，开启后台自动整理，配置兼容 AI 后即可自动入库和准备双版本。源文件保留，正式曲库不要放进下载目录。已有资源在“整理曲库”预览、打标签和批量准备。TV 默认随机原唱开场，无需更换 APK。

也可以直接在后台监控 B 站收藏夹，无需 bili-sync。配置“AI 歌曲信息识别与刮削”后自动整理标题和标签；信息不全到“待核对”补充。PC 支持包单独下载 haohaochang-pc-worker.zip，双击 start.cmd，复制显示的地址与密钥到 NAS。分离调度 PC 优先、兼容 API 后备，最多并行两项。
